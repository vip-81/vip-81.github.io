捕魚機規則快速看

每次開火都會消耗「每發成本」，子彈命中魚隻時扣除其 HP；HP 歸零即擊破，玩家獲得「魚種獎勵 × 砲台倍率」的虛擬點數。五段火力分別是 ×1 到 ×5，成本與傷害同步提高。

彈道與命中：為什麼不能只檢查點碰撞

子彈速度是每秒 1120 像素，畫面寬度 960。若在某個 frame 子彈從魚的左側跳到右側，而程式只檢查「目前位置是否在魚的圓內」，就會發生穿透（tunneling）。本實作保存上一幀位置，將兩個位置連成線段，再計算線段與魚圓心的最短距離。

function segmentCircleHit(x1, y1, x2, y2, cx, cy, radius) {
  const dx = x2 - x1;
  const dy = y2 - y1;
  const lengthSquared = dx * dx + dy * dy || 1;
  let t = ((cx - x1) * dx + (cy - y1) * dy) / lengthSquared;
  t = clamp(t, 0, 1);
  const px = x1 + dx * t;
  const py = y1 + dy * t;
  return (px - cx) ** 2 + (py - cy) ** 2 <= radius * radius;
}

這個做法對圓形魚體已經足夠；若魚的碰撞形狀不規則，可改用多個圓或膠囊體。重點是碰撞必須用「這一段移動」而不是「這一瞬間的位置」。

魚群 AI：小魚群聚，大魚巡航

小丑魚以簡化 boids 成群：檢查 130px 內的同伴，計算凝聚力（往群心靠）與分離力（避免重疊），再加上原本的向右或向左速度。為了控制 O(n²) 成本，魚池上限只有 36 隻，且只比較同一個 school ID 的魚。

河豚、海龜、鯊魚與龍王使用正弦擾動的巡航路徑：vy = baseVy + sin(phase × 1.6 + seed) × amplitude。這讓大魚看起來有生命感，但不會像 boids 一樣不可預測，方便美術與伺服器對齊。

魚隻離開畫面一定距離後就回收，而不是刪除物件；下次生成直接覆寫欄位。這是固定容量池的核心：記憶體不會隨時間線性成長。

砲台倍率與期望值

假設某魚種的基礎獎勵是 R、HP 是 H，砲台倍率是 M、每發成本是 C、命中率是 p。擊破一隻魚的期望成本約為 (H / (p × M)) × C，期望回報是 R × M。兩者相除就能得到該魚種的粗略回報率。

提高倍率會同時提高傷害與成本，因此不一定更划算；真正的平衡需要把魚種權重、HP、獎勵、砲台成本與玩家命中率一起模擬。這也是為什麼正式捕魚機的倍率與魚群生成必須由伺服器控制。

重要：本頁的「自動捕魚」是 demo 輔助模式，會優先鎖定高價值魚種。它不是外掛，也不代表正式產品應允許無限制自動化；伺服器仍需速率限制與風險控制。

同步伺服器結算：前端只送意圖

在多人捕魚機中，魚群與子彈通常是共享狀態。常見做法是：

  1. 伺服器產生魚群、HP、路徑與可見時間，廣播給同一房間的客戶端。
  2. 客戶端只送出「開火」意圖（角度、時間、砲台等級），不送「我打中了」。
  3. 伺服器依權威彈道與魚群狀態判定命中、扣血、擊破與派彩，再廣播結果。
  4. 客戶端收到結果後播放爆炸與加分動畫；若預測與伺服器不同，以伺服器為準。

為了避免延遲感，客戶端可以先用相同參數做預測，但必須在收到伺服器結果時校正。結算紀錄應包含局單 ID、玩家、魚隻 ID、子彈 ID、時間戳、傷害、餘額變化與簽章。

物件池、背景快取與離屏繪製

本頁有三個固定容量池：36 條魚、48 發子彈、180 個粒子。背景（海水漸層、光柱、珊瑚、海床、水波紋）只繪製一次到離屏 canvas，之後每幀只做一次 drawImage。這比每幀重畫數百條貝茲曲線便宜得多。

當分頁切到背景時，visibilitychange 會取消 requestAnimationFrame 並儲存餘額，回來才重新啟動。這能避免背景分頁持續消耗 CPU，也避免長局遊玩後記憶體累積。

手機、鍵盤與無障礙

Canvas 設有 tabindex="0" 與 role="application"，可用左右方向鍵調整角度、空白鍵或 Enter 開火。所有擊破與餘額變化都會透過 aria-live 公告。觸控使用 Pointer Events，並以 touch-action: none 避免瀏覽器手勢干擾瞄準。

若使用滑鼠，移到海面即可瞄準，按住連續射擊；放開即停止。若使用自動捕魚，系統會在瞄準誤差小於 0.08 弧度時開火。

常見問題

捕魚機的命中判定為什麼不用點碰撞？

子彈速度可達每秒 1100 像素，若只檢查子彈當前位置是否落在魚的圓內，低幀率時可能直接穿過。改用上一幀到這一幀的線段與魚的圓做碰撞，能避免 tunneling。

砲台倍率越高越好嗎？

不一定。倍率提高會增加每發成本與傷害，但若命中率低或魚種 HP 高，期望回報不一定更好。正式產品的倍率與魚群權重必須一起調整，並由伺服器結算。

為什麼魚群要分開處理？

小魚使用簡化 boids 產生群聚感，大魚使用正弦路徑維持可預測的巡航；兩者視覺需求與運算成本不同。物件池固定容量也能避免長局遊玩時記憶體持續成長。

自動捕魚是外掛嗎？

不是。它是 demo 內建的輔助模式，會優先鎖定高價值魚種並自動開火；正式產品若提供類似功能，必須受伺服器速率限制與風險控制。

正式捕魚機如何防止作弊？

魚群生成、子彈命中、傷害與派彩都必須由伺服器權威計算或驗證。前端只送瞄準與開火意圖，伺服器依時間戳、彈道與魚群狀態結算，並記錄可稽核的局單。
