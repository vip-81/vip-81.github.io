輪盤規則快速看

歐式輪盤有 37 個格位：0 到 36。0 是綠色，其餘數字依固定順序交錯紅黑。玩家在下注時間內把籌碼放到號碼或外圍區域，莊家轉動輪盤並投入小球，球停在哪一格，該格與相關组合注即中獎。

  • 單號（Straight）：選一個號碼，賠 35:1（返還 36 份，含本金）。
  • 紅／黑、單／雙、大／小：賠 1:1；0 不算任何一邊。
  • 打注（Dozen）：1–12、13–24、25–36，賠 2:1。
  • 直行（Column）：1,4,7…、2,5,8…、3,6,9…，賠 2:1。

本頁沒有 split、street、corner、line 等「組合注」，只有單號與六種外圍注；這是刻意的簡化，讓下注板在手機上仍可準確點擊。正式產品若加入組合注，必須把每個格位的命中集合與派彩寫成資料表，而不是用視覺位置推測。

以單號為例：命中機率是 1/37，命中時返還 36 份（35 份利潤加本金），所以期望值為 (1/37) × 36 = 0.9730。外圍注的算法相同，只是把 36 換成 2 或 3。這就是為什麼「賠率越高越好」是錯的：高賠率只是低命中率的補償，長期期望值並沒有變高。

RTP 是長期理論值，不是單局或單晚的結果。短期波動可能讓你連續命中，也可能長時間不中；任何「必勝法」都無法改變負期望值。

結果先定，動畫後播

很多輪盤實作會讓球的物理模擬決定結果，這在單機 demo 看似合理，但在產品中很危險：不同裝置的幀率、暫停、背景切換與物理參數都可能改變落點，讓「公平性」無法驗證。本頁刻意反向操作：

  1. 按下「轉動輪盤」後，先以 randomInt(37) 抽出結果。
  2. 找出結果在輪盤序列中的索引，計算輪盤需要轉到的角度。
  3. 用 ease-out quint 在 4.7 秒內把輪盤與球帶到目標，並在過程中播放 tick 音效。
  4. 動畫結束才呼叫 settleSpin(result)，依結果結算所有注。
const result = randomInt(37);
const pocketIndex = WHEEL_SEQUENCE.indexOf(result);
const segment = (Math.PI * 2) / WHEEL_SEQUENCE.length;
const desired = modAngle(-pocketIndex * segment);
const wheelTarget =
  wheelRotation + Math.PI * 2 * (5 + Math.random() * 2)
  + modAngle(desired - wheelRotation);

這樣做有兩個好處：第一，結果與動畫完全解耦，低階手機或開啟「減少動態」都不會影響機率；第二，正式產品可以改成先向伺服器請求結果，再用同一個 animateTo(result) 播放，前端不需要重寫流程。

Canvas 轉輪與球體動畫

轉輪以 560×560 的邏輯座標繪製，依 devicePixelRatio 放大畫布，避免高解析螢幕模糊。37 個扇形用 arc 繪製，數字隨輪盤旋轉但保持由圓心向外閱讀；球则使用極座標 (angle, radius) 移動，半徑從 238 收到 205，模擬球落入內圈。

每次動畫幀只重繪整個輪盤一次，沒有離屏快取，因為輪盤本身會旋轉，快取反而需要額外的旋轉合成。真正需要快取的是靜態背景與符號紋理，而不是會整體旋轉的輪盤。

若使用者開啟 prefers-reduced-motion，程式會直接定位到結果、縮短結算等待，不播放 tick 與長時間旋轉。這不只是「無障礙加分」，也能避免前庭功能敏感者不適。

下注板與狀態管理

下注鍵以 n:0 到 n:36 表示單號，外圍注使用 red、black、dozen:1 等字串。這種設計讓 localStorage 的內容可讀、可清洗，也讓派彩函式可以用同一個 betReturn(key, result) 處理所有注。

function betReturn(key, result, amount) {
  if (key.startsWith("n:")) {
    return Number(key.slice(2)) === result ? amount * 36 : 0;
  }
  const red = result !== 0 && RED_NUMBERS.has(result);
  switch (key) {
    case "red": return red ? amount * 2 : 0;
    case "black": return result !== 0 && !red ? amount * 2 : 0;
    case "odd": return result !== 0 && result % 2 === 1 ? amount * 2 : 0;
    case "dozen:1": return result >= 1 && result <= 12 ? amount * 3 : 0;
    default: return 0;
  }
}

旋轉期間，所有下注鍵與籌碼都會被停用，避免「旋轉中改注」造成結算與畫面不一致。這個限制由 phase 控制：只有 idle 能下注，spinning 只能等待。

公平性與正式環境

本頁的亂數來自瀏覽器的 Web Crypto，並使用拒絕取樣避免 % 37 的模數偏差。這比 Math.random() 好，但仍然不是可驗證的賭場級 RNG：玩家可以修改前端、替換函式，或直接改 localStorage。

正式產品應由伺服器：

  • 持有 RNG 與輪盤序列，產生並簽章每一局結果；
  • 以局單 ID 記錄投注、結果、派彩、時間戳與玩家；
  • 在局前公開 server seed 的雜湊，局後揭示 seed 供玩家重算；
  • 將餘額與局單放在伺服器，前端只送下注意圖與播放結果。

只有「結果先定」還不夠；如果結果由前端決定，玩家仍可竄改。公平性需要「權威來源」與「可驗證紀錄」同時成立。

斷線重連與本機恢復

本頁把餘額、籌碼面額、目前投注、上一局投注、近期結果與已轉次數寫入 localStorage。重新載入時會：

  • 驗證餘額為非負整數，否則回到預設值；
  • 只接受合法的下注鍵與正整數金額；
  • 只保留 0–36 的近期結果，最多 12 筆；
  • 重建下注板與 HUD，並顯示上一局結果。

局中旋轉不會持久化：若在球落下前重新載入，會回到可下注狀態，桌面投注仍在。正式產品應在重連後向伺服器查詢該局是否已結算，避免重複下注或重複派彩。

鍵盤、螢幕閱讀器與手機

Canvas 只負責視覺；所有結果、餘額、投注與狀態都有 DOM 文字。下注格是真正的 <button>，具備可讀的 aria-label，內容包含「號碼＋顏色＋目前下注」。籌碼按鈕使用 aria-pressed 表示目前面額。

手機版下注板會壓縮為 3 欄外圍注，號碼格最小 39px；所有可點區域都大於 24×24 CSS px。若你使用鍵盤：Tab 到下注格按 Enter，或聚焦「轉動輪盤」後按空白鍵。

常見問題

這個輪盤是美式還是歐式？

這是歐式單零輪盤，共有 37 格（0 到 36）。只有一個 0，因此理論 RTP 為 97.30%，高於美式雙零輪盤的 94.74%。

輪盤的結果是在動畫中產生的嗎？

不是。結果在轉輪開始前就以 crypto.getRandomValues 決定，動畫只負責把輪盤與球帶到對應位置。即使切到背景、低幀率或開啟減少動態，結果都不會改變。

0 號算紅色還是黑色？

0 號是綠色，不屬於紅色或黑色，也不符合單數、雙數、大、小與打注。只有直接下注 0 號或包含 0 的其他组合注才會命中。

輪盤的理論 RTP 是多少？

歐式單零輪盤的所有標準投注在長期下的理論 RTP 都是 97.30%，也就是賭場優勢約 2.70%。不同投注的波動與命中率不同，但期望值相同。

重新整理後下注會保留嗎？

會。餘額、籌碼面額、目前桌面投注、上一局投注、近期結果與轉數都存在 localStorage。重新載入後會清洗資料並恢復；正式產品應由伺服器持有餘額與局單。

可以用鍵盤玩嗎？

可以。所有下注格與籌碼都是按鈕，Tab 可依序聚焦，Enter 或空白鍵下注。焦點不在按鈕時，空白鍵可直接轉動輪盤。結果與餘額會透過 aria-live 公告。
