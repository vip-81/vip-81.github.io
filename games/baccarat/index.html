百家樂規則快速看

百家樂的目標是下注「閒家勝」、「莊家勝」或「和局」，以及可選的對子。牌面點數：A 算 1 點，2–9 依面值，10／J／Q／K 算 0 點；總和取個位數，例如 7 + 8 = 15，計為 5 點。

  • 閒家與莊家各發兩張牌。
  • 任一方 8 或 9 點（natural）時，雙方都不補牌。
  • 閒家 0–5 點補一張，6–7 點停牌。
  • 莊家依「莊家點數」與「閒家第三張牌的點數」套用標準補牌表。
  • 莊家勝抽水 5%；和局時閒／莊投注退回；對子賠 11:1。

莊家補牌表：最容易寫錯的地方

很多簡化版會讓莊家「5 點以下就補」，這在閒家補了第三張牌時是錯的。標準規則是根據閒家第三張牌的點數決定，例如莊家 3 點時，只有在閒家第三張牌不是 8 時才補。

公平性驗證：指紋只是第一步

本頁在建立牌靴後，將每張牌的唯一 ID 串接並計算 SHA-256，取前 16 碼作為指紋。這能讓你在重新整理後確認「牌靴沒有被換掉」，但它不能證明洗牌過程沒有被操縱。

正式系統通常採用 provably fair 流程：

  1. 伺服器先產生 server seed，並公開其雜湊（commitment）。
  2. 玩家提供 client seed；雙方 seed 混合後洗牌。
  3. 局後揭示 server seed，玩家可重算雜湊與洗牌結果。
  4. 每局結果以伺服器簽章封存，並保留可稽核的局單。

若沒有賽前 commitment，事後才公布的 seed 沒有證明力；若沒有伺服器簽章，前端仍可被篡改。這三件事必須一起做。

下注互動與斷線重連

本頁把餘額、牌靴、剩餘張數、珠盤路、統計與目前桌面投注寫入 localStorage。重新載入後會：

  • 驗證牌靴結構與索引是否合法，不合法就建立新靴；
  • 清洗投注資料，只接受五種合法下注與正整數金額；
  • 重新計算指紋，避免直接信任舊資料；
  • 恢復珠盤路與統計，讓戰績連續。

局中發牌不持久化：若在發牌動畫中重新載入，會回到可下注狀態。正式產品應由伺服器保留局單，客戶端重連後查詢「這局是否已結算」，而不是自行重播。

無障礙與行動版

下注區是可聚焦的按鈕，會朗讀「下注區名稱＋目前下注金額」；牌面以 DOM 呈現，螢幕閱讀器可讀出「黑桃 A」等文字，不依賴 Canvas。發牌與結算結果會同時更新可見狀態與 aria-live 區域。

手機版下注區會改為 2–3 欄，牌面縮小但不隱藏點數。若開啟減少動態，發牌延遲會縮短為 70ms，仍保留每張牌的順序。

常見問題

百家樂的補牌規則是固定的嗎？

是。閒家 0–5 點補牌、6–7 點停牌；莊家依閒家第三張牌套用標準補牌表。若閒家沒有補牌，莊家 0–5 點補牌、6–7 點停牌。本頁實作的是 8 副牌的標準規則。

為什麼莊家贏只賠 95%？

莊家勝率較高，賭場以 5% 抽水平衡優勢。投注 100 點莊家，贏時返還 100 點本金加 95 點利潤；和局時莊閒投注通常退回。

牌靴指紋能證明公平嗎？

牌靴指紋只能證明「這副牌在洗牌後沒有被改動」，不能單獨證明結果隨機或未被操縱。正式系統需要賽前 commitment、賽後揭示 seed、伺服器簽章與可稽核局單。

重新整理後會發生什麼？

牌靴、剩餘張數、餘額、珠盤路與統計會從 localStorage 恢復，並重新計算指紋。局中尚未完成的發牌不會保存，重新載入後會回到可下注狀態。

和局與對子的賠率是多少？

標準賠率為和局 8:1、閒對 11:1、莊對 11:1。和局時閒家與莊家投注退回，對子投注依是否命中結算。高賠率伴隨高波動，長期期望值通常較低。
