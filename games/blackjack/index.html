21 點 Blackjack 試玩：6 副牌、S17 與基本策略

選籌碼、按「發牌」，然後用加牌、停牌、加倍或分牌把點數打到最接近 21 點。這是一張可直接玩的 21 點牌桌，也是一份關於軟硬牌、牌靴、賠付與斷線恢復的實作拆解。

重點摘要

21 點的技術難點不是發牌動畫，而是「狀態」：現在輪到哪一手、A 要算 1 還是 11、分牌後哪一手已完成、重新載入後莊家是否該繼續補牌。本示範用 6 副牌、S17、Blackjack 3:2、一次分牌，並把牌靴與未完成牌局存在本機；正式產品必須由伺服器持有牌靴與結算。

21 點規則快速看

玩家與莊家各發兩張牌。玩家的目標是讓手牌點數盡量接近 21 點，但不能超過；超過就是「爆牌」，立即輸掉該手。玩家可以先加牌（Hit）、停牌（Stand）、加倍（Double）或分牌（Split），莊家則依固定規則補牌，沒有決策空間。

  • 牌值：2–10 依面值，J／Q／K 算 10 點，A 可算 1 或 11 點。
  • 軟牌：A 仍以 11 點計算且不會爆牌，例如 A+6 是「軟 17」。
  • Blackjack：首兩張牌就是 21 點（A＋10 點牌），賠 3:2；分牌後的 21 點不算 Blackjack。
  • 莊家：本桌為 S17，莊家軟 17 停牌；硬 16 以下補牌。
  • 加倍：任意兩張牌可加倍，加注後只補一張牌。
  • 分牌：同點數的兩張牌可分牌一次；分 A 每手只補一張即停牌。

本示範未提供保險、投降與多次分牌。這些規則會改變最佳策略與莊家優勢，不能直接把本頁的策略表套用到所有牌桌。

軟牌與硬牌：A 的兩種算法

A 可以算 1 或 11，但同一手牌只能選一種算法。程式通常先以 11 計算，若總和超過 21 再把 A 降為 1。這種「至少有一張 A 仍算 11」的手牌稱為軟牌；沒有 A 或 A 已被迫降為 1 的手牌稱為硬牌。

function blackjackValue(cards) {
  let total = 0;
  let aces = 0;
  for (const card of cards) {
    if (card.rank === 1) { aces += 1; total += 11; }
    else total += Math.min(card.rank, 10);
  }
  let soft = aces > 0;
  while (total > 21 && aces > 0) {
    total -= 10;
    aces -= 1;
    soft = aces > 0;
  }
  return { total, soft };
}

為什麼要區分軟硬？因為軟 17 與硬 17 的補牌風險完全不同。軟 17 補一張牌不會立刻爆牌（A 可降為 1），硬 17 補牌則有超過 21 的風險。莊家 S17 對玩家較有利，約比 H17 好 0.2 個百分點，實際差異取決於其他規則。

基本策略：不是保證贏，而是最小化劣勢

基本策略是根據「玩家手牌 × 莊家明牌」查表的最佳動作，目標是讓長期期望值最大化。它不能保證單局勝利，也無法逆轉莊家優勢；在標準規則下，完整基本策略可把莊家優勢壓到約 0.5%，也就是玩家 RTP 約 99.5%。

賠付、RTP 與莊家優勢

一般勝局賠 1:1，和局退回投注，Blackjack 賠 3:2。假設投注 100 點，拿到 Blackjack 時返還 250 點（100 本金＋150 利潤）。若牌桌把 Blackjack 改為 6:5，同樣的 100 點只返還 220 點，莊家優勢會增加約 1.4 個百分點，長期影響非常大。

RTP 與莊家優勢是長期統計，不是單局保證。即使使用完美基本策略，短期仍可能連續輸；任何投注系統都無法改變負期望值。

牌局狀態：比發牌動畫更難的部分

21 點的流程包含多個階段：idle（等待下注）、dealing（發初始四張牌）、player（玩家決策）、dealer（莊家補牌）、settled（已結算）。每個階段可用的按鈕不同，例如只有 player 能加牌，只有 idle 或 settled 能改注碼。

分牌會讓「一手」變成「兩手」，並且可能出現「第一手已完成、第二手還在進行」的狀態。程式必須追蹤 active 索引，並在目前手牌完成後尋找下一手未完成的手牌；兩手都完成才進入莊家回合。這就是為什麼只靠一個 isPlaying 布林值會很快失控。

還有一個常見坑：分牌 A 的自動停牌。若兩張 A 分牌後仍允許加牌，玩家可能取得多個 21 點，破壞規則與期望值。本實作在分牌時就將兩手標記為完成，並在畫面顯示「分牌 A · 自動停牌」。

公平性與牌靴指紋

本頁以 Fisher–Yates 洗 6 副牌，並在建立牌靴後計算 SHA-256 前 16 碼作為指紋。指紋可以幫你確認「重新整理後還是同一副牌靴」，也能在除錯時比對狀態，但它不能證明洗牌沒有被操縱。

正式系統應採用：

  1. 伺服器產生 server seed，賽前公開其雜湊（commitment）。
  2. 玩家提供 client seed，雙方 seed 混合後洗牌。
  3. 局後揭示 server seed，玩家可重算雜湊與牌序。
  4. 每局結果以伺服器簽章封存，並保留可稽核的局單。

此外，正式產品還需處理「牌靴中途換靴」與「未完成局」的伺服器狀態。客戶端不應自行決定是否換靴，也不應在重連後重播已派彩的牌。

斷線重連：恢復到哪一步？

本頁把牌靴、牌靴索引、餘額、莊家牌、玩家手牌、目前手牌索引、階段、結果文字與統計寫入 localStorage。重新載入後會：

  • 驗證每張牌的 rank 與 suit，拒絕不合法資料；
  • 清洗手牌，只保留有正數投注且牌面合法的手牌；
  • 若階段是 player，恢復玩家回合與目前手牌；
  • 若階段是 dealer，自動讓莊家繼續補牌；
  • 若階段是 settled，顯示上一局結果，等待「下一局」。

注意：dealing 階段的資料不會被保存，因為發牌中的暫時狀態沒有保存價值。正式產品則應由伺服器記錄「已發牌但未結算」的局單，重連後查詢結果，而不是由前端推測。

鍵盤、螢幕閱讀器與手機

牌面以 DOM 呈現，每張牌都有可讀文字（例如「黑桃 A」），不依賴 Canvas。莊家點數、玩家點數、結果與餘額都會更新；重要變化也會透過 aria-live 公告。按鈕在不可用時會設為 disabled，避免使用者按下無效操作。

鍵盤快捷鍵：H 加牌、S 停牌、D 加倍、P 分牌；焦點在按鈕或連結時不會觸發，避免與 Enter／空白鍵衝突。手機版操作按鈕會改為 2 欄，牌面縮放但不隱藏點數。

常見問題

21 點的基本規則是什麼？

玩家與莊家各發兩張牌，目標是讓手牌點數接近 21 但不超過。2–10 依面值，J／Q／K 算 10 點，A 可算 1 或 11 點。玩家可加牌、停牌、加倍或分牌；莊家依固定規則補牌，本示範為軟 17 停牌（S17）。

為什麼 Blackjack 賠 3:2？

Blackjack 指首兩張牌就是 21 點（A 加一張 10 點牌），機率約 4.8%。3:2 的賠付讓它的期望值高於一般勝局，也是 21 點之所以強調「基本策略」的原因之一。若賠 6:5，莊家優勢會明顯上升。

軟 17 是什麼？為什麼莊家 S17？

軟 17 指手牌含一張可算 11 點的 A，總點數為 17（例如 A+6）。S17 表示莊家在軟 17 停牌，H17 則表示要補牌。S17 對玩家較有利，本示範採用 S17。

分牌 A 為什麼只補一張？

若兩張起始牌都是 A，分牌後每手各得一張 A；為避免玩家透過反覆分牌取得多個 21 點，標準規則是每手只補一張牌就自動停牌。本示範遵循此規則，且只允許分牌一次。

重新整理後未完成的牌局會保留嗎？

會。牌靴、牌靴索引、餘額、手牌、目前輪到哪一手、莊家牌與統計都會存在 localStorage。重新載入後會驗證資料並恢復；若當時輪到莊家，會自動繼續補牌。正式產品應由伺服器持有牌靴與局單。

這個 21 點 demo 可以用真錢玩嗎？

不行。所有籌碼都是虛擬點數，無法兌換現金或任何有價物。正式真錢產品必須由伺服器產生牌靴、簽章結算、持有餘額，並符合當地年齡驗證、限額與反洗錢法規。
