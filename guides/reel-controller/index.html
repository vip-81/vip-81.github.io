5×3 滾輪控制器：啟動、依序減速、超調回彈與結果透傳

這篇給出一個不綁定渲染引擎的滾輪控制器：純 JavaScript、每幀回傳位移資料，用六狀態 FSM 管理流程。五軸由左到右每 200ms 開始減速，停輪時先向下超調再向上回彈對齊。最重要的是：控制器不計算中獎，矩陣與中獎線索引全部由後端給定，前端只是把滾輪帶到指定位置。

先說結論

把「結果」與「動畫」拆開：後端先給 5×3 矩陣與中獎線，控制器只做時間軸與位移。減速用三次 Hermite 讓起速與最大速度連續，回彈用 sin(πu)·(1−u) 製造超調後收斂。客戶端沒有任何一步會重新計算賠付線。

六狀態狀態機

流程固定為 Idle → SpinUp → LoopScroll → SpinDown → Bounce → ResultShow。全域狀態由時間軸決定，單軸另有更細的 spinUp / loop / spinDown / bounce / locked 階段，方便渲染層個別處理。

狀態觸發允許動作
Idle初始／reset()start()
SpinUp0 → spinUpMs速度由 0 加速到 maxVelocity
LoopScrollspinUpMs → 第一軸減速點等速滾動，至少 minLoopMs
SpinDown軸 0 開始減速軸 i 於 spinUp + minLoop + 200×i 開始減速
Bounce軸 4 減速結束向下超調 → 回彈對齊
ResultShow全部軸鎖定只回傳後端 payload，不判定中獎

減速與回彈的物理

加速段用 v(t)=vmax·u²，積分得到位置 p=vmax·T·u³/3，起手不會瞬移。減速段用三次 Hermite，指定起點 p₀、終點 p₁、起始速度 v₀ 與結束速度 0：

p = h₀₀p₀ + h₁₀(v₀T) + h₀₁p₁
v = [h₀₀′p₀ + h₁₀′(v₀T) + h₀₁′p₁] / T

為避免 Hermite 在距離過短時出現倒退，停位距離會補上整圈直到 D ≥ v₀·T/2。回彈用 p = p₁ + overshoot·sin(πu)·(1−u)：u=0 與 u=1 時皆為 0，最大值約在 u≈0.3，形成「向下超調再向上對齊」的手感。

重要：超調只改變顯示座標，最終鎖定位置一定是後端指定的 strip 索引。即使掉幀、切背景或開啟減少動態，最終符號仍一致。

嚴格禁止客戶端計算中獎

控制器完全不知道賠付表。它接收：matrix（5 軸 × 3 行結果）、paylines（後端回傳的中獎線索引）、seed，以及選擇性的 stopIndices。它輸出的是同一份資料的唯讀副本，不會比對符號、不會加總倍率、不會改寫 paylines。

const controller = createReelController({ staggerMs: 200 });
const frame = controller.start({
  matrix: [[A,B,C],[B,C,D],[E,A,B],[C,D,A],[B,B,C]],
  paylines: [1, 8],   // 後端決定，前端只顯示
  seed: 42,
}, performance.now());

若 strip 中找不到後端指定的三格連續視窗，控制器只在該軸的本地副本上把視窗釘成後端值，並不回寫共享 strip，也不會影響其他軸——這是視覺對齊，不是結果運算。

每幀資料格式

update(now) 回傳 { state, elapsedMs, reels, result }。每個 reel 含 position（symbol 單位的連續位置）、fraction、offsetPx（渲染用 translateY）、velocity、phase、stopped、visible（目前三格）與 targetIndex。呼叫端可自行決定用 Canvas、DOM 或 WebGL 呈現。

模組位於 /assets/js/lib/reel-controller.js，另有 reel-controller.d.ts 提供 TypeScript 型別。
