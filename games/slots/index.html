老虎機規則快速看

這台機台是 5 滾輪 × 3 列、固定 10 條賠付線。每次旋轉的總投注會平均分配到 10 條線，因此「每線投注」等於總投注除以 10。連線一律從最左邊的滾輪開始，連續 3、4 或 5 個相同符號才算完成。

  • Wild 可以替代 10、J、Q、K、A、GEM、COIN、SEVEN，但不會替代 SCATTER。
  • SCATTER 不依賴賠付線，出現在畫面任意位置都算；3 個以上同時賠付並觸發免費旋轉。
  • 免費旋轉 期間所有獎金 ×2，可再次被 SCATTER 觸發，剩餘次數上限 50。
  • Big Win 依「本局贏分 ÷ 總投注」分級：10 倍進入演出、25 倍 BIG WIN、50 倍 MEGA WIN、100 倍 LEGENDARY。

滾輪物理與停輪手感

老虎機的「物理感」不是真的模擬剛體，而是三個視覺訊號的組合：加速曲線、停輪回彈、動態模糊。本實作在旋轉開始時就為每條滾輪決定最終停位，再計算需要多轉幾圈才能抵達：

const finalPos = randomInt(reel.strip.length);
const startPos = reel.position % reel.strip.length;
const forward = mod(finalPos - startPos, reel.strip.length);
const extraTurns = 4 + index * 2 + randomInt(2);

reel.anim = {
  start: now,
  startPos,
  delta: forward + extraTurns * reel.strip.length,
  duration: 980 + index * 165,
  finalPos,
};

更新時使用四次方的 ease-out，讓滾輪在前段保持高速、後段快速收斂。停輪後再疊加一個 260ms 的正弦回彈，位移只有 10px，目的是讓「停住」有重量，而不是硬切。

旋轉中的動態模糊以低透明度重複繪製一次符號，成本比濾鏡低，也不會在低階手機上造成大面積合成負擔。若使用者開啟「減少動態」，動畫縮短為 320ms 並移除回彈與震動。

連線判定：由左至右，Wild 不是萬能

判定時先看第一條滾輪的符號，再逐輪往右延伸。若遇到非候選符號就停止；Wild 可以接續任何一般符號，但 SCATTER 不參與線獎。為了避免同一條線同時符合多個候選，程式會選出賠付最高的一組。

for (let reelIndex = 0; reelIndex < REEL_COUNT; reelIndex += 1) {
  const symbol = grid[reelIndex][line[reelIndex]];
  if (symbol === candidate || symbol === "WILD") count += 1;
  else break;
}

SCATTER 則獨立掃描整個 5×3 盤面。這種「線獎 + 全盤計數」的雙軌設計很常見，也意味著後端必須同時回傳盤面、線獎明細與 SCATTER 數量，前端不能自行推測。

Free Spin 狀態機：把流程從 if 裡拿出來

老虎機最容易出現 bug 的地方不是賠付，而是「現在到底能不能按」。例如：旋轉中調整投注、免費遊戲中誤觸旋轉、Big Win 還沒關閉就再次旋轉。這些問題用散落的布林值會很難維護，因此本實作使用明確的 FSM。

idle→ SPIN → spinning→ REELS_STOPPED → evaluating→ FS_START / BIGWIN / END → freespin↔ bigwin
  • idle：只接受 SPIN，投注可調整。
  • spinning：等待五條滾輪停止，拒絕下注與再次旋轉。
  • evaluating：計算線獎、SCATTER、免費遊戲與 Big Win 等級。
  • freespin：由計時器自動推進，剩餘次數歸零才回到 idle。
  • bigwin：顯示分級演出，只能按「繼續」離開；若仍有免費轉數則接到 freespin。

FSM 的 guard 讓「能不能做」與「做了之後做什麼」分開；轉移紀錄保留最近 20 筆，除錯時可以直接看到狀態變化，不必在幾十個 console.log 裡找答案。

Big Win 分級與演出節奏

Big Win 的門檻以「總投注」為基準，而不是單線投注。這樣不同投注額的玩家會感受到一致的比例回饋。本示範的級距如下：

數字會從 0 跑到最終贏分，但派彩在演出前就已經入帳，因此重新整理或關閉視窗不會重複領取。正式產品應由伺服器回傳「已結算」狀態，前端只負責顯示。

Symbol 物件池與離屏紋理

老虎機每轉都會產生大量短命物件。若每次都 new 粒子或重新繪製符號，長局遊玩容易出現垃圾回收尖峰。本實作做兩件事：

  1. 固定容量粒子池：180 個粒子預先配置， spawn 時覆寫欄位，生命結束只設 active = false。
  2. 離屏符號紋理：每種符號只畫一次到 256×256 的隱藏 canvas，之後用 drawImage 縮放。

主迴圈只在有動畫時才 requestAnimationFrame；靜止時完全停止重繪，行動裝置的耗電與發熱會明顯較低。這也是「Canvas 遊戲不一定比較耗電」的關鍵：重點是有沒有在不需要時繼續畫。

公平性：前端 RNG 只適合展示

本頁使用 crypto.getRandomValues 與拒絕取樣，避免 Math.random 的可預測性與模數偏差。但這仍然只是前端展示：玩家可以修改 JavaScript、攔截請求或直接改 localStorage。

正式的老虎機必須由伺服器：

  • 持有 RNG 與符號權重，產生盤面與特色結果；
  • 以局單 ID 記錄投注、結果、派彩與時間戳；
  • 回傳伺服器簽章，讓前端與稽核端驗證結果未被竄改；
  • 在需要時可公開 seed commitment，並在局後揭示 seed。

RTP 也應由後端以大量模擬或精確列舉計算，而非用單一 demo 的短期結果推估。

鍵盤與無障礙

Canvas 本身對螢幕閱讀器不友善，因此所有重要狀態都同步到 DOM：餘額、投注、贏分、免費轉數與 FSM 狀態都有可讀文字；每次旋轉與中獎也會透過 aria-live 公告。空白鍵在焦點不在按鈕時可旋轉；Big Win 對話框會把焦點移到「繼續」，Esc 可關閉。

若你使用鍵盤：Tab 到「旋轉」按鈕後按 Enter／空白鍵，或直接按空白鍵。若你開啟減少動態，滾輪會快速定位，仍會公告結果。

常見問題

這個老虎機的 RTP 是多少？

示範版沒有宣稱固定 RTP。RTP 由賠付表、符號權重、賠付線數與特色規則共同決定，必須用蒙地卡羅模擬或精確列舉計算。正式產品會由伺服器設定並公開可驗證的數字。

Free Spin 怎麼觸發？

任一時段出現 3 個以上 SCATTER 即觸發：3 個 10 轉、4 個 15 轉、5 個以上 20 轉。免費遊戲期間所有獎金 ×2，且可再次觸發，剩餘轉數上限為 50。

Wild 和 Scatter 有什麼不同？

Wild 可以替代一般符號組成連線，但不會替代 SCATTER；SCATTER 不依賴賠付線，只要在畫面任意位置出現 3 個以上就會賠付並觸發免費遊戲。

為什麼要讓滾輪回彈？

回彈是停輪後的短暫位移與衰减，用來模擬實體滾輪的慣性，讓停輪更有重量感。它只影響視覺，不改變已抽出的最終位置。

正式產品可以直接用這份程式碼嗎？

不行。示範版在前端產生結果並存在 localStorage；正式產品必須由伺服器產生並簽章結果、持有餘額與局單，前端只負責送出請求與播放對應動畫。
